# Independent review, 2026-10-14: mLateOn retrieval, precon benchmark harness, reported results

Scope: (A) the mLateOn late-interaction implementation in the eval path (`LateInMemory`) and the shipped Docker path (NextPlaid + int8 ONNX); (B) the precon benchmark harness (EXP-007/009/010), with a skim of the agentic (EXP-006) and static (EXP-001/003/004/008) evals; (C) the write-ups and registry against the run records. Read-only; no LLM calls. One NextPlaid container (`mtg-search:latest`, `--entrypoint next-plaid-api --int8 --query-length 512`) and one PyTorch process (model loaded once, index loaded once, 2 threads) were used for a small parity check, then stopped. Repo state reviewed: HEAD `c53c752`.

## Verdict on the mLateOn question

**(a) Eval path (`LateInMemory`, used by every eval and the benchmark): correct.** Queries get the single added token `[Q]▁` (id 256000) after `<bos>`, documents `[D]▁` (256001); `query_length`/`document_length` 8192, no query expansion, empty skiplist, token-level L2 normalisation, fp32 compute over fp16 stored tokens. This matches the model's own `config_sentence_transformers.json` and NextPlaid's `onnx_config.json`. The stored `tokens.npy` (T4, fp16, revision `bbd883a` = HF `main`) re-encodes on CPU to per-token cosine ≥ 0.9998. MaxSim, padding, mask pre-filtering, top-k and row alignment are right.

**(b) Shipped path (Docker, NextPlaid 1.8.5, int8 reduce-range ONNX): queries are encoded the same way, but the served ranking is not the benchmarked ranking.** Token counts are identical to the ST path on all 8 probe queries; per-token cosine vs fp32 is 0.98–0.99 mean (0.93 min on a 34-token `find_similar` query). End-to-end, the shipped top-10 agrees with exact MaxSim on 85% of slots in my 8-query sample (top-50: 79%); `docker/README.md` measured 72.3% on all 363 eval queries. Top-1 differed on 3 of 8 queries. The loss splits about evenly between int8 (encoder-only 86% @10) and the PLAID index (index-only 87.5% @10, 79.5% @50). Nothing in the benchmark exercises this path (`ShippedToolset` refuses a Docker backend), so every "shipped" number in EXP-007/009/010 is for the exact in-process ranker.

## Findings

### Major

#### M1. The benchmark never measures the retriever that ships; the shipped ranking differs from it on ~15–28% of top-10 slots

- **Where.** `bench/precon/harness/tools.py:357-360` (`ShippedToolset`: "shipped toolset needs an in-process backend (late or bm25)"); `tools.py:142-145` (`LateInMemory.from_dir`); `src/mtg_search/nextplaid.py:57-58` (`int8=True`, `query_length=512`), `:189-207`; `docker/build_index.py:85` (`nbits: 4`), `:36,90-108` (500-doc incremental `/update`, default `start_from_scratch`); `docker/README.md:82-102`; `index/models/lightonai__mLateOn-int8rr/quantization.json` ("top-10 overlap 72% (fp32 82%)"); `spike/nextplaid.md:96` ("A quality comparison against a one-shot build is still open").
- **Evidence (my run, 8 queries, unfiltered corpus, exact MaxSim = brute force over `tokens.npy`):**
  ```
  ST query token counts: [7, 13, 14, 12, 6, 15, 12, 34]   NP (int8) query token counts: [7, 13, 14, 12, 6, 15, 12, 34]
  per-token cos vs ST: mean 0.982–0.994, min 0.928 (34-token query)
  mean enc_only10 0.863  e2e10 0.850  e2e50 0.787  index_only10 0.875  index_only50 0.795
  top-1 differs: "Counter target spell unless its controller pays {3}." (Flaccify vs Mana Leak),
                 "destroy all creatures" (Fumigate vs Begin Anew), "I keep losing to fliers..." (3/8 queries)
  ```
  `docker/README.md:88-90`: reference 28.8 nDCG@10, int8-rr via NextPlaid 28.3, top-10 overlap 72.3%; fp32 ONNX via NextPlaid only 82.5% overlap.
- **Impact.** Every write-up that says "the shipped MCP" / "mLateOn-only retrieval" (precon_benchmark.md, mcp_instructions.md, mcp_surface_smoke.md) benchmarked the exact fp32 ranker. The EXP-009/010 conclusions (tool-use triggering, validity) do not depend on exact ranks, but any statement about what the shipped server returns (and the EXP-001/003/008 retrieval numbers, if read as "what users get") does. Separately, a PLAID index with `nbits=4` losing 12.5% of the exact top-10 and 20% of the top-50 *with the same query vectors* is more loss than PLAID normally shows; the README notes that raising `n_ivf_probe`/`n_full_scores` did not help, which points at the incremental centroid build (k-means on the first 999 docs, then grown to 10,420 partitions) that the spike flagged as untested.
- **Fix.** (1) Add a parity script and run record (`eval/experiments/nextplaid_parity.py` → `runs/*.json`, registry row): exact vs NextPlaid at top-10/50, encoder-only vs index-only, filtered as the server filters (`include_funny=False`). (2) Try a one-shot centroid build (first `/update` with several thousand docs, or NextPlaid's rebuild option) and the fp32 ONNX; pick by measured recall-vs-exact. (3) Run at least the final shipped configuration of the precon benchmark with `--backend docker` (add a Docker backend to `ShippedToolset`), or state in each write-up that retrieval was the exact in-process ranker.

#### M2. Headline effects rest on percentile-bootstrap CIs at n=14; the exact sign test the harness computes disagrees and is never reported; no multiplicity handling

- **Where.** `bench/precon/scorer.py:455-474` (`paired_bootstrap` returns `sign_test_p`; `bootstrap_ci` is a percentile bootstrap of the mean); `bench/precon/run.py:339-362` (`compare` prints it). `eval/experiments/mcp_instructions.md:9,54-63`; `precon_benchmark.md:54-62`; `REGISTRY.md:15`.
- **Evidence** (recomputed with `bench.precon.run.compare` on the episode files; diff = arm − base):
  ```
  add.ndcg@10  v3 - v1            +0.139 [+0.048,+0.236]  sign p=0.424
  add.ndcg@10  v3al-deferred - v1 +0.090 [-0.002,+0.183]  sign p=0.022
  add.validity mcp-hint - none    +0.079 [+0.021,+0.143]  sign p=0.109
  add.validity v3al-deferred - v1 +0.057 [+0.011,+0.118]  sign p=0.227
  add.validity v3 - v1            +0.079 [+0.025,+0.132]  sign p=0.021
  add.pop_drift v3 - v1           +0.857 [+0.447,+1.276]  sign p=0.013
  add.pop_drift mcp-hint - none   +1.062 [+0.720,+1.393]  sign p=0.002
  ```
  The EXP-009 headline (+0.139, "the best ADD score of any arm", registry row) is a mean driven by a few precons; under the sign test it is p=0.42. Each write-up reports ~24 paired contrasts (6 arms × 4 metrics) and highlights those whose 95% CI excludes 0; at that count, one or two exclusions are expected by chance.
- **Impact.** "ADD nDCG@10 +0.139 [+0.048, +0.236] vs v1" (mcp_instructions.md:9, REGISTRY EXP-009) is over-stated. What survives both tests: popularity drift (v3, system-prompt hint, mcp-hint) and v3's ADD validity.
- **Fix.** Report `sign_test_p` next to every CI (it is already computed); name one primary metric per experiment before running; treat the rest as exploratory; or use a BCa/t bootstrap and 3 repeats as the plan requires (`docs/benchmark_precon_plan.md:150`).

#### M3. The 14-precon test split has been used for 21 adaptive arms; the plan's "test once per frozen config" rule is not followed or counted

- **Where.** `docs/benchmark_precon_plan.md:160` (T5: iterate on train, select on dev, "run test once per frozen config … REGISTRY records the number of test evaluations"); `bench/precon/runs/` (21 `_test`/`smoke` records); `REGISTRY.md:13,15,16` (no count); `eval/experiments/mcp_surface_smoke.md` §Recommendation ("Ship e6desc_slim").
- **Evidence.** Arms were designed after seeing the previous arm's test result (mcp → mcp-hint; v2 → v3 → v3al; e1…e6). EXP-010 picks the best of 7 arms on 14 ADD episodes each; the paired difference of the winner vs the shipped baseline is `+0.021 [-0.091, +0.129]`, sign p=0.79 (e1desc `+0.009 [-0.057, +0.080]`). The two runs of the *same* shipped config differ by 21 points of search rate (36% vs 57%) and 0.032 nDCG, which is the noise floor the selection is made inside.
- **Impact.** Winner's curse on the EXP-010 recommendation and, more mildly, on v3/alwaysLoad. The dev split (15 precons, "certainly in training") exists for exactly this selection step and was used only for the probe.
- **Fix.** Select on dev, freeze, run test once with ≥3 repeats for the final comparison (shipped vs e6desc_slim); add a "test evaluations so far: N" field to the EXP-007 registry row.

### Minor

#### m1. Leakage pre-flight does not cover the model-facing tool text; it names a dev gold card

- **Where.** `bench/precon/harness/leakage.py:45-52` (gold-name check runs on system prompt + few-shots only); `src/mtg_search/server.py:471` (`SIMILAR_DOC`: `find_similar("Rhystic Study", …)`), `bench/precon/harness/surfaces.py:17,26` (same example in v1/v2).
- **Evidence.** `bench.gold_names(["dev","test"]) ∩ surface text = {'Rhystic Study'}`; it is a **dev** label, not a test label, so no test result is affected.
- **Fix.** Run the gold-name and `LEAK` checks over `ShippedToolset.instructions` and every tool description before an episode, or drop card-name examples from the surface.

#### m2. Name resolution bug was live during all EXP-007/009 runs (fixed after)

- **Where.** `git show eaa0919 -- src/mtg_search/server.py` (18:46; "exact lookups prefer a card's full name over another card's face name"). All EXP-007/009 run records are at `07c342d…0186c92`/`8b41b20` (before the fix).
- **Impact.** `get_card`/`find_similar`/`check_cards` on a name that is also a DFC face returned the DFC (e.g. "Lightning Bolt"). The agents made 27 (`mcp-hint`) and 30 (`v2-sphint`) `get_card` calls; a few may have shown the wrong card. Small, but EXP-009 is not exactly reproducible from HEAD.

#### m3. Headline ADD metrics penalise land picks although the prompt says "Lands are allowed"

- **Where.** `bench/precon/scorer.py:218-245` (`score_side`: picks are partitioned; headline P@20 divides by 20, nDCG@20 loses the slot); `bench/precon/harness/prompts.py:31`.
- **Evidence.** Land picks out of 280: none 6, mcp 8, mcp-hint 13, v1 3, v3 10, v3al-deferred 19. Tool-using arms pick more lands, so the headline score is biased *against* them by up to ~7% of slots.
- **Fix.** Score headline metrics over headline picks only (`k = min(k, n_headline)`), or score lands on the headline side; state the choice in the write-ups.

#### m4. Run records are mislabelled and mostly from a dirty tree

- **Where.** `bench/precon/run.py:302` (`"experiment": "EXP-007"` hard-coded: all EXP-009/010 records say EXP-007); `run.py:58` (`dirty_bench`): 17 of 21 LLM run records have `dirty_bench: true`, e.g. `shipped-v1_test` at `200aaca` dirty, `v3-deferred`/`v3al-deferred` at `8b41b20` dirty.
- **Fix.** Take the experiment id from the CLI; commit before each run (the registry's own rule).

#### m5. Tool-call budget in the Claude Code proxy is not thread-safe and over-budget attempts are not counted

- **Where.** `bench/precon/harness/cc_proxy.py:30-50` (`CallBudget.handle` mutates `self.n` without a lock), `:85-91` (`anyio.to_thread.run_sync` per call: parallel tool calls in one turn race); `claude_code.py:195-196` (`tool_calls` keeps only `tool_call` events, not `over_budget`).
- **Impact.** The cap can be exceeded by the number of parallel calls in a turn; `tool_calls_per_episode` under-reports attempts. No episode in the records hit the cap, so no number changes today.

#### m6. No `oracle_ids_sha256` check when the eval/benchmark load embeddings

- **Where.** `src/mtg_search/retrievers/late.py:110-114` (`from_dir` reads meta but never compares the digest); `bench/precon/harness/tools.py:139-145`; `eval/run.py`. Only the Docker path (`artifacts.check_index`) and `scripts/refresh.py:297-299` verify it.
- **Impact.** A refreshed `cards.parquet` with stale `tokens.npy` would silently misalign rows in every eval. Today they match (`1bff7b49…`).
- **Fix.** Compare `meta["oracle_ids_sha256"]` to the loaded card table in the callers (or in `from_dir` given the oracle ids).

#### m7. The README/quantization.json parity numbers have no script or run record

- **Where.** `docker/README.md:82-102`; `index/models/lightonai__mLateOn-int8rr/quantization.json` "validation"; nothing in `eval/experiments/runs/`, no registry row.
- **Fix.** See M1 (1).

#### m8. EXP-001 registry wording

- **Where.** `REGISTRY.md:7` ("Late vs best non-late: +3.9 [+2.0, +6.0] para+deck, +22.4 handwritten"); `eval/results.md:185-192`.
- **Evidence.** The +3.9 row is `rrf(dense+mLateOn)` vs `dense` with the best system of each group chosen on the same queries ("selection on the test set favours both groups equally"); the single-model contrast is +2.9 [+0.4, +5.5].
- **Fix.** Name the two systems and the selection in the row.

#### m9. Deferred-loading arms always spend one turn on `ToolSearch` for `final_answer`

- **Where.** `claude_code.py:126-128`, transcripts (`ToolSearch {"query": "select:mcp__mtg-search__final_answer"}` first in every deferred episode); `surfaces.py:38` (`_always_load` excludes `final_answer`).
- **Impact.** Turn and prompt-token comparisons between upfront and deferred arms in mcp_instructions.md are confounded by this harness artefact (noted only in mcp_surface_smoke.md). Consider always-loading `final_answer`.

#### m10. EXP-006 bootstrap keys read backwards

- **Where.** `eval/agentic/results/main.json` `bootstrap["AvsC:recall@5"] = -0.040` is C − A (the write-up's "C − A −4.0 [−7.1, −1.1]" is right, the key is not).

## Verified OK

mLateOn, eval path:
- Model config at `bbd883a` (= HF `main`): `query_prefix "[Q] "`, `document_prefix "[D] "`, `query_length`/`document_length` 8192, `do_query_expansion false`, `skiplist_words []`. sentence-transformers 6.1 promotes these into prompts `{'query': '[Q] ', 'document': '[D] '}`, `query_expansion None`, `MultiVectorMask(skiplist_words=[])`, token-level `Normalize`; tokenisation `['<bos>','[Q]▁','▁draw','▁a','▁card','.','<eos>']` (ids `[2, 256000, …, 1]`), identical token counts to NextPlaid's ONNX path. `meta.json` records the same prompts, revision, `doc_max_length 8192`, 0 truncated docs, max 398 tokens.
- Stored tokens vs CPU re-encode (Rhystic Study, 34 tokens): per-token cosine min 0.9998; unit norms.
- `maxsim_scores`/`build_buckets`/`scores`: first-token padding cannot change a max; `amax(dim=1).sum(dim=1)` is MaxSim; tests `test_maxsim_matches_bruteforce`, `test_bucketed_maxsim_matches_reference` pass; my own brute force agrees with the shipped top-1 on 5/8 queries and with the encoder-only check as expected.
- Filtering: `allowed` is applied before scoring (sub-bucket gather when < 50% allowed, `-inf` otherwise) and again in `top_k`; `_MaskBackend` converts row indices to a mask; `CardService.cards.select(...)` keeps row order; `cards_for_eval` touches only the `tags` column.
- Multi-query: `depth = max(50, 2*limit)`, `rrf` k=60, equal weights, per-list dedupe, stable ties; raw user query never auto-added.
- `find_similar` uses the card's `doc_text` as a `[Q]` query (design choice); no truncation on either path (max 398 tokens < 512).

Shipped path:
- `doc_rows.npy` is the identity mapping for all 34,646 docs (read back from the container metadata); `check_index` verifies card count and digest at startup; `build_index.py` refuses a digest mismatch; health reports `num_embeddings 2,179,176` = `meta.n_tokens`, `avg_doclen 62.9`, `nbits 4`, `quantized true`, prefix ids 256000/256001.
- `search()` sends `subset` only when it is a strict subset; rows outside the table are dropped; stdout is kept clean (child stdout → stderr); `--read-only` handled by copying the index.

Harness:
- Isolation (checked in transcripts of three arms): `tools` = proxy tools only (plus `ToolSearch` in deferred arms), `mcp_servers` = the proxy only, `apiKeySource: none`, `permissionMode default`, `memory_paths.auto` under the per-episode temp dir, no `~/.claude/CLAUDE.md`, user settings contain no hooks/MCP servers. `check_isolation` raises `LeakError` (never retried) on any extra tool or server.
- System prompts in transcripts match `prompts.system_prompt` for `none`, `mcp-hint` and `shipped` (no tool text, no budget line for shipped); deck rendering has no tags, product name or popularity strings; `preflight` identifier/LEAK checks cover system + user prompt.
- Retry handling: `attempt` markers written before each `claude -p`; only proxy events after the last marker count; `final_answer` args parsed via `parse_final` (`tool_args`), text fallback otherwise; all 42-episode runs ended with `final_answer`, 0 errors.
- Budget messages identical between GLM loop and proxy; caps per plan (5/10/12).
- Scorer vs plan: thresholds (.50/.30/.15 cuts, .30/.15/.05 adds), validity rules (exact names, in deck, not commander, identity, legality, singleton with basic/any-number exceptions, Game Changer limit in rank order after cuts), nDCG ideal = k largest label gains per precon per kind, P@k with fixed k, R/F1 over grade ≥ 2, macro mean over precons with repeats averaged first, 10k-resample CI, paired bootstrap on common precons, Kendall τ (raw vs continuous gains = 1.0 for ADD). `edhrec_rank` used only offline (popularity oracle, drift).
- Fast unit tests: 89 passed (`test_retrievers`, `test_precon_scorer`, `test_precon_harness`, `test_precon_claude_code`, `test_fusion`, `test_server`).
