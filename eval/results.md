# Retrieval evaluation results

Generated by `uv run --extra models python eval/run.py` (cached rankings in `eval/.cache/`).

- Corpus: 34,646 cards (`data/cards.parquet`). Every query is restricted to its `filters`; funny cards are always excluded.
- Each component retrieves top-100; fusions are RRF (k=60) over those lists, truncated to 100.
- nDCG@10 uses graded gains (2 for `graded` cards, 1 otherwise, linear gain). Recall@50/100 and MRR@10 are binary.
- Latency: CPU (6 cores), warm, one query at a time, includes query encoding + scoring + top-k with the filter mask. Fusion latency = sum of component latencies (sequential) + RRF time. Other processes were running on the machine, so treat p95 as noisy.
- Weighted fusions (`=0.5`, `=2`) were picked after looking at unweighted results on these same sets, so their numbers are optimistic.

## Observations

- Paraphrase `-para` queries with no relevant card in the top 10: rrf(dense+mLateOn=2) 51/111, late-mLateOn 54/111, dense 56/111, sparse 74/111. Most paraphrase pairs are ties at 0, so the paraphrase set separates systems on a minority of queries.
- Paraphrase `-need` queries with no relevant card in the top 10: rrf(dense+mLateOn=2) 78/111, late-mLateOn 82/111, dense 86/111, sparse 91/111. Most paraphrase pairs are ties at 0, so the paraphrase set separates systems on a minority of queries.
- Late interaction here runs **in-process** (`LateInMemory`, brute-force MaxSim over fp32 token matrices): late-mLateOn p50 105 ms incl. query encoding, dense p50 120 ms. So these quality numbers do not require NextPlaid; they price the model choice, not the runtime.
